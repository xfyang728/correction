# 批注错位问题分析报告与改进方案

## 摘要

针对用户提出的五个批注错位假设，通过代码验证得出结论：**5 个假设中 1 个完全成立、4 个部分成立**。首要错位源是 Y clamp 无条件 replace（假设 5）和文字渲染基线补偿偏小（假设 4）。部分假设提到的旧问题（70px 阈值、img_h/2 列检测 bug、默认走等宽切分）已在当前代码中修复或从未存在。

| 假设 | 结论 | 嫌疑度 |
|---|---|---|
| 1. 预处理改变图像尺寸 | 部分成立（deskew 旋转内容致坐标系错位，仅扫描件倾斜≥0.3°） | 低（数字 PDF 无影响） |

### 假设 4：PDF 映射基线问题 — 部分成立

**验证结论**：Y 翻转公式正确，字号公式正确，但基线补偿偏小。

**代码证据**：
- [pdf_annotator.py L45-51](file:///d:\MyCode\correction\auto_marker\core\pdf_annotator.py#L45-L51)：Y 翻转公式 `y_page = page_height - y_pixel/img_h*page_height` ✓ 正确
- [pdf_annotator.py L106](file:///d:\MyCode\correction\auto_marker\core\pdf_annotator.py#L106)：字号 `font_size = max(min(bh * 0.9, 24), 8)` ✓ bh 是 PDF 点
- [pdf_annotator.py L112](file:///d:\MyCode\correction\auto_marker\core\pdf_annotator.py#L112)：**基线补偿 `text_y = min(y0_page, y1_page) + bh * 0.1`** ⚠️ 偏小

**问题分析**：ReportLab `drawString(x, y, text)` 的 y 是文字基线左端点。中文字体基线比例通常在 20-25%（ascender ratio），当前 10% 导致渲染文字整体偏下约 10-15% bh。

### 假设 5：坐标修正过度 — 成立（首要嫌疑）

**验证结论**：Y clamp 无条件 replace，无置信度门控，无独立开关，且注释与代码不符。

**代码证据**：
- [qwen_vl_recognizer.py L896-921](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py#L896-L921)：`_clamp_chars_y_to_region` 直接用 region/手写框 y 范围替换模型 y，**不是 clamp 是 replace**，丢失逐字 y 差异
- [qwen_vl_recognizer.py L1391-1392](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py#L1391-L1392)：`RENDER_TEXT_MODE=True` 时仍调用 Y clamp
- [qwen_vl_recognizer.py L1395-1396](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py#L1395-L1396)：`RENDER_TEXT_MODE=False` 时也调用 Y clamp
- [recognition_config.py L59-62](file:///d:\MyCode\correction\auto_marker\core\recognition_config.py#L59-L62)：注释说 "True = 跳过坐标 clamp"，**与代码不符**

**问题分析**：
- 所有字都被赋予同一 `(norm_y0, norm_y1)`，多行题或上下偏移字的 y 差异被抹平
- 无开关可关闭，想测试"不 clamp 的效果"必须改源码
- X rescale 已有几何门控（跨度>1.3× 或偏移>80px），比 Y clamp 克制

## 改进方案（按优先级排序）

### 改进 1：修正 RENDER_TEXT_MODE 注释与代码不符（低风险，高优先级）

**问题**：注释说 "True = 跳过坐标 clamp"，但实际两条分支都调用 Y clamp。

**改什么**：修正 [recognition_config.py L59-62](file:///d:\MyCode\correction\auto_marker\core\recognition_config.py#L59-L62) 的注释，反映实际行为。

**改为什么**：
```python
# P3: 文字渲染模式开关
# True = 将识别文字直接渲染到 bbox 位置（覆盖原文），应用 y-clamp + 条件性 x-rescale
# False = 传统标记模式（勾/圈/三角），应用 y-clamp + x-clamp
RENDER_TEXT_MODE = True
```

**为什么**：注释与代码不符会误导维护者，是假设 5 中"预期落空"的根因。

### 改进 2：基线补偿调整（低风险，中优先级）

**问题**：`bh * 0.1` 偏小，中文字体实际基线比例约 20-25%。

**改什么**：[pdf_annotator.py L112](file:///d:\MyCode\correction\auto_marker\core\pdf_annotator.py#L112) 的基线补偿系数。

**改为什么**：
```python
# ReportLab drawString 的 y 是基线左端点，中文基线约为 bbox 高度的 20%
text_y = min(y0_page, y1_page) + bh * 0.2
```

**为什么**：中文字体 ascender ratio 约 0.8（即基线在字符高度 20% 处），10% 偏小导致文字偏下。

**验证**：对比调整前后的批注 PDF，观察文字是否更居中于 bbox。

### 改进 3：Y clamp 增加开关与真正的 clamp 行为（中风险，高优先级）

**问题**：Y clamp 是 replace 非 clamp，丢失逐字 y 信息，无开关。

**改什么**：
1. 在 `recognition_config.py` 新增 `Y_CLAMP_ENABLED = True` 开关
2. 将 `_clamp_chars_y_to_region` 的 replace 行为改为真正的 clamp（仅在模型 y 超出 region 范围时才 clamp 到边界）

**改为什么**（伪代码）：
```python
# recognition_config.py
Y_CLAMP_ENABLED = True  # 新增：Y 坐标 clamp 开关

# qwen_vl_recognizer.py _clamp_chars_y_to_region
def _clamp_chars_y_to_region(char_items, region, img_h, handwriting_boxes=None, img_w=0):
    from core.recognition_config import Y_CLAMP_ENABLED
    if not Y_CLAMP_ENABLED:
        return char_items  # 开关关闭时保留模型 y
    ...
    for ci in char_items:
        x0, y0, x1, y1 = ci["bbox_norm"]
        # 真正的 clamp：仅当模型 y 超出 region 范围时才修正
        clamped_y0 = max(y0, norm_y0)  # 下边界 clamp
        clamped_y1 = min(y1, norm_y1)  # 上边界 clamp
        clamped.append({**ci, "bbox_norm": (x0, clamped_y0, x1, clamped_y1)})
    return clamped
```

**为什么**：
- replace 抹平所有逐字 y 差异（多行题、上下偏移字），clamp 保留模型 y 的相对信息
- 开关允许快速 A/B 测试，对比"有 clamp vs 无 clamp"的效果
- 真正的 clamp 只修正超出 region 的部分，对模型 y 合理的字不做任何改动

**风险**：模型 y 系统性偏移（多题共享同一 y 值）是已知问题，真正的 clamp 可能无法完全修正这种偏移。需要 A/B 测试验证。

### 改进 4（可选）：deskew 坐标系一致性（高风险，低优先级）

**问题**：layout 用 deskew 后图像，VL 用原始图像，坐标系错位（仅扫描件）。

**改什么**：让 layout 也用原始图像，或让 VL 也用 deskew 后图像。

**为什么不推荐立即实施**：
- 当前测试样本是数字 PDF，不受影响
- 改动涉及架构调整（layout 依赖 CLAHE 增强后的检测质量）
- 风险高，收益低（仅扫描件受益）

## 假设与决策

1. **聚焦数字 PDF 场景**：当前测试样本是数字 PDF，假设 1（deskew 错位）不影响，暂不处理。
2. **Y clamp 改进需要 A/B 测试**：replace → clamp 可能无法完全修正模型 y 系统性偏移，需要对比测试。如果 clamp 效果不如 replace，保留 replace 但加开关。
3. **基线补偿 0.2 是经验值**：中文字体 ascender ratio 约 0.8，但不同字体（微软雅黑/黑体/宋体）略有差异，0.2 是折中值。
4. **不改进版面分析阈值**：当前 90/55 在 200 DPI 下工作良好，无 DPI 自适应需求。
5. **不改进等宽切分**：默认不走此路径，优先级低。
