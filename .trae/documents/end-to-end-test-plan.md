# 端到端测试验证计划 — "检测-分离-提取"三阶段流水线

## 一、摘要

本计划覆盖三阶段流水线（文本检测 → 版面分析与分离 → 手写识别 → 比对 → 批注）的端到端测试验证，确保：

1. 流水线完整执行无 API 错误
2. 各阶段输出符合预期（检测框、手写区域、字符识别、比对状态）
3. 批注 PDF 正确生成
4. 数据库写入正确

---

## 二、当前状态分析

### 已实现的流水线模块

| 文件 | 功能 | 状态 |
|------|------|------|
| `core/text_detector.py` | 阶段一：PP-OCRv6 det 模型文本检测 | ✅ 已实现 |
| `core/layout_analyzer.py` | 阶段二：基于 bbox 高度的版⾯分析（手写/印刷/拼音分类 + 题号检测） | ✅ 已实现（**无 PPStructure 依赖**） |
| `core/handwriting_recognizer.py` | 阶段三：裁剪手写子图 → PP-OCRv6 rec 识别 → 等宽切分单字 | ✅ 已实现 |
| `core/grader.py` | Needleman-Wunsch DP 比对 + 置信度门控 + 按题统计 | ✅ 已实现 |
| `core/pdf_annotator.py` | 批注 PDF 生成（逐字/按题双模式） | ✅ 已实现 |
| `core/image_processor.py` | 图像预处理 | ✅ 已实现 |
| `monitor/processor.py` | 流水线调度 | ✅ 已实现 |

### 已知风险

| 风险 | 说明 |
|------|------|
| **数据提取路径不一致** | `text_detector.py` 从 `json['res']`（嵌套列表格式）提取 dt_polys；`handwriting_recognizer.py` 从 `json['rec_texts']`（dict 键）提取识别结果。两种路径是否正确需验证 |
| **文档与实际代码不一致** | `架构设计.md` §6.5 仍引用 PPStructure（实际代码已改为 bbox 高度规则）；§6.6 引用旧 API 参数 `det=False, rec=True` |
| **PaddleOCR 3.7 predict() 行为** | `predict()` 同时跑检测和识别，`text_detector.py` 和 `handwriting_recognizer.py` 各自独立调用 `predict()`，每次都会跑全量检测+识别，存在重复计算 |

### Step 5: 修复发现的问题

如果测试中出现错误，按以下优先级修复：

1. **API 错误**（如 `AttributeError`、`KeyError`）— 最高优先级，阻塞流水线
2. **数据提取问题**（检测框/识别结果为空）— 检查 json 路径
3. **分类不准确**（手写/印刷误分类）— 调整 bbox 高度阈值
4. **文档不一致** — 同步更新 `架构设计.md`
