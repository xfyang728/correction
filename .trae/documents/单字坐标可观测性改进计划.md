# 单字坐标可观测性改进计划

## 摘要

当前已是 Qwen3-VL 为主（`RECOGNITION_ENGINE=page_level`），单字坐标来自模型输出的归一化 bbox，经 `_rescale_chars_x_to_region` + `_clamp_chars_y_to_region` 修正。但 page_level 内部有 **4 条坐标来源路径**，目前无法区分每题/每字实际走了哪条路径。

本计划添加 `coord_source` 字段标记每条字符记录的坐标来源，并在日志和验证工具中输出统计，**为后续数据驱动的改进决策提供依据**。不改变任何坐标生成逻辑。

---

## 一、当前状态分析

### 1.1 page_level 模式的 4 条坐标来源路径

基于 [qwen_vl_recognizer.py](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py) 的 `recognize_page_level` 函数（L1231-1501）：

| 路径 | 触发条件 | 代码位置 | 单字坐标来源 | 文本来源 | 精度 |
|------|---------|---------|------------|---------|------|
| **A. JSON 模型坐标** | JSON 解析成功且非 invalid，非合并题 | L1394-1437 | Qwen3-VL bbox_norm + rescale + clamp | Qwen3-VL 识别 | 高 |
| **B. 合并题拆分** | chars 数 > 标准答案+2 | L1398-1407 | Qwen3-VL bbox + split + rescale + clamp | Qwen3-VL 识别 | 中高 |
| **C. invalid 等宽切分** | 坐标无效（bbox 格式错误/零宽） | L1441-1465 | `_equal_width_split`（region 范围） | **标准答案**（非学生答案） | 低 |
| **D. JSON 失败 fallback** | JSON 解析失败/零产出 | L1481-1485 → `_fallback_text_path` | `_equal_width_split`（region 范围） | 旧文本解析（Qwen3-VL 文本） | 低 |

### 1.2 当前结果格式

每条字符记录的 dict 结构（[qwen_vl_recognizer.py](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py) 各产出处）：
```python
{
    "page": 0,
    "bbox_pixel": (x0, y0, x1, y1),
    "char": "随",
    "confidence": 0.85,
    "question_idx": 0,
    "img_pixel_w": 1653,
    "img_pixel_h": 2312,
    "engine": "qwen_vl",  # 已有的引擎标记（粗粒度）
}
```

**问题**：`engine` 字段只标记引擎（qwen_vl），无法区分 4 条路径。路径 C 用标准答案替代学生答案（L1446），路径 D 用等宽切分，这些都是潜在误差源，但目前无法从结果中识别。

### 1.3 误差来源诊断（对应用户描述的 4 种模式）

| 误差模式 | 对应路径 | 当前状态 |
|---------|---------|---------|
| 整体偏上/偏下 | 路径 A/B 的 Y clamp 未完全修正 | 已实现混合策略（replace/clamp/保留） |
| 整体偏左/偏右 | 路径 A/B 的 X rescale 逻辑 | 已实现双重触发（跨度>1.3× 或偏移>80px） |
| 字间距太均匀 | **路径 C/D 的等宽切分** | **无标记，无法识别** |
| 个别字错位 | 版面分析 question_idx 分配错误 | 已实现多层回退匹配 |

**核心盲点**：路径 C/D 的等宽切分无法从结果中识别，无法量化其影响。

## 二、改动详情

### 改动 1: qwen_vl_recognizer.py — 添加 coord_source 字段

**目标**：在 4 条路径的产出处为每条字符记录添加 `coord_source` 字段。

**字段值定义**：
- `"model_json"` — 路径 A（JSON 模型坐标）
- `"model_merged_split"` — 路径 B（合并题拆分）
- `"fallback_invalid"` — 路径 C（invalid 等宽切分）
- `"fallback_text_parse"` — 路径 D（JSON 失败 fallback）

**改动位置**（4 处）：

1. **路径 A（L1408-1437）**：JSON 模型坐标路径，在 `char_items` 转 dict 时添加
   - 当前代码：`r["engine"] = "qwen_vl"` 已在 L1432 附近
   - 改动：在设置 engine 的同时设置 `r["coord_source"] = "model_json"`

2. **路径 B（L1398-1407）**：合并题拆分路径
   - 当前代码：`split_results = _split_merged_json_chars(...)` 返回 list[dict]
   - 改动：在 `all_results.extend(split_results)` 之前，遍历 `split_results` 设置 `r["coord_source"] = "model_merged_split"`
   - **或**在 `_split_merged_json_chars` 函数内部（L1148-1228）统一设置

3. **路径 C（L1441-1465）**：invalid 等宽切分路径
   - 当前代码：`split = _equal_width_split(...)` 返回 list[dict]
   - 改动：在 `for r in split: r["confidence"] = 0.50` 循环中同时设置 `r["coord_source"] = "fallback_invalid"`

4. **路径 D（L1504-1568）**：`_fallback_text_path` 函数
   - 当前代码：`split_results = _equal_width_split(...)` 返回 list[dict]
   - 改动：在 `all_results.extend(split_results)` 之前遍历设置 `r["coord_source"] = "fallback_text_parse"`

**向后兼容**：
- `coord_source` 是新增字段，不影响现有代码
- `engine` 字段保留不变（粗粒度标记）
- 其他引擎路径（paddle/qwen_vl/dual）不添加 `coord_source`（仅 page_level 模式有）

### 改动 2: pipeline_service.py — 添加坐标来源统计日志

**目标**：在 Step D 手写识别完成后，输出坐标来源分布统计。

**改动位置**：[pipeline_service.py](file:///d:\MyCode\correction\auto_marker\services\pipeline_service.py) L304 附近（`all_results` 累积完成后）

**新增代码逻辑**：
```python
# 坐标来源统计（仅 page_level 模式有意义）
from collections import Counter
coord_sources = Counter(r.get("coord_source", "unknown") for r in all_results)
if any(k != "unknown" for k in coord_sources):
    logger.info("第 %d 页: 坐标来源统计 %s",
                page_idx + 1, dict(coord_sources))
```

**输出示例**：
```

```

**目标**：在验证工具中添加 coord_source 分布统计，方便人工检查。

**改动位置**：[_verify_annotation_position.py](file:///d:\MyCode\correction\auto_marker\tools\_verify_annotation_position.py) L53 之后（现有统计表之后）

# 坐标来源统计
print("\n坐标来源分布:")
coord_sources = Counter(r.get("coord_source", "unknown") for r in results)
for source, count in sorted(coord_sources.items()):
    print(f"  {source:>25}: {count:>3} 字 ({count/len(results)*100:.1f}%)")

print(f"\n{'q_idx':>6} {'coord_source':>25} {'n':>3}")
print("-" * 40)
q_source = defaultdict(Counter)
for r in results:

## 三、假设与决策

### 3.1 假设
- 4 条路径的代码位置基于 [qwen_vl_recognizer.py](file:///d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py) L1370-1568 的静态分析
- 上一会话 E2E 测试 62 字全部正确，说明路径 A/B 占主导，C/D 触发较少
- `coord_source` 字段不影响 grader.py 的 DP 比对（grader 只读取 char/bbox_pixel/confidence）

### 3.2 决策
- **不改坐标生成逻辑**：本计划只添加可观测性，不改变 4 条路径的坐标生成行为
- **仅 page_level 模式添加**：其他引擎（paddle/qwen_vl/dual）的 `coord_source` 为 `unknown`，不强制添加
- **保留 engine 字段**：`coord_source` 是 `engine` 的细粒度补充，不替代
- **_split_merged_json_chars 内部设置**：路径 B 在函数内部统一设置 `coord_source`，避免外部遍历

### 3.3 不改动的项
- 不改 `_equal_width_split`（路径 C/D 仍用等宽切分，仅标记）
- 不改 invalid 路径的标准答案替代逻辑（仅标记，后续按数据决策）
- 不改 PP-OCRv6 字级检测配置（方向 B，暂不探索）
