# 批注错位五假设验证与改进计划

## 摘要

针对用户提出的批注错位五层面分析报告，通过代码探索验证五个假设的成立情况。结论：**假设 4、5 已修复不成立；假设 1、2、3 部分成立但多数子问题已修复**。当前残余风险集中在 **page_level 路径的坐标空间一致性**（假设 1）和 **等宽切分累积偏移**（假设 3）。本计划提出 3 项针对性改进，按优先级排序。

### 1.2 各假设详细验证

#### 假设 1：坐标来源与图像尺寸不一致 — 部分成立（潜在风险）

**用户描述的问题**：
- 预处理改变图像尺寸但映射时用错误尺寸
- 倾斜校正旋转矩阵未传递

**代码实际情况**：
- `image_processor.py:128` — `warpAffine(img, matrix, (w, h), ...)` 输出尺寸 = 输入尺寸，**画布不扩大**
- `image_processor.py:47-53` — 低分辨率上采样（min(h,w) < 1000）会改变尺寸，但 200 DPI 不触发
- `pipeline_service.py:226` — `det_boxes` 在 `processed_np`（已 deskew）上检测
- `pipeline_service.py:252-266` — `page_level` 路径用 `original_np`（未 deskew），但 `question_regions` 在 `processed_np` 空间

**核心风险**：当扫描有倾斜（≥0.3°）触发 deskew 时：
- `question_regions`、`handwriting_boxes` 在 processed_np（已旋转）坐标空间
- Qwen3-VL 在 original_np（未旋转）上识别，返回的归一化坐标 → 像素时用 original_np 维度
- 两空间存在旋转偏移（0.5° × 2000px ≈ 17px）

**当前为何未触发**：
- 默认 `QWEN_VL_USE_DESKEW=False`（recognition_config.py:57）
- 多数测试扫描无倾斜或倾斜很小

**用户描述的"映射公式用错尺寸"不成立**：`pdf_annotator.py:223-224` 从每条结果读取 `img_pixel_w/h`，与识别器写入时一致，坐标系封闭一致。

#### 假设 2：版面分析手写区域定位 — 部分成立（描述过时）

**用户描述的问题**：
- 高度阈值粗糙（h≥70px 为手写，h≤50px 为拼音）
- 无列检测，按 y 排序分配题号
- 题号仅依赖正则匹配
- 手写区域未覆盖整个答案行

**代码实际情况**：
- `layout_analyzer.py:41-42` — 实际阈值 `HANDWRITTEN_HEIGHT_MIN=90`、`PINYIN_HEIGHT_MAX=55`（**非 70/50**）
- `layout_analyzer.py:185-210` — **非纯高度判断**，含题号标记的框一律判为印刷体（反向纠正）
- `layout_analyzer.py:537-570` — **列检测已实现**（`_split_into_columns` 按 markers 间最大 x 间隙 > 150px 拆列）
- `layout_analyzer.py:51-79` — 题号检测支持 `(1)`/`①`/`1.`/`1、` 四种格式 + 多层回退（`_infer_missing_paren_markers`、圈号回退、文本关键词回退）
- `layout_analyzer.py:227-259` — **sub_region 条带提取**：印刷体框 h≥130px 时取底部 55% 作为手写条带（启发式）

**残余问题**：
- sub_region 条带提取是启发式，假设手写总在题号下方，对横向排版失效
- `layout_analyzer.py:653` — `y_start = m["y_center"]` 用 marker 中心 y 而非顶部，可能漏掉 marker 上方字符

#### 假设 3：手写识别与切分误差 — 部分成立

**用户描述的问题**：
- bbox 中心点匹配提取文本
- 等宽切分单字位置不准
- DP 比对跳字导致索引错位

**代码实际情况**：
- `handwriting_recognizer.py:110-134` — **中心点匹配确认**，且 `unmatched_boxes.pop(best_idx)` 首匹配即停，**一个手写框内多 OCR 记录时只匹配第一个，后续遗漏**
- `handwriting_recognizer.py:178-191` — **等宽切分确认**（PaddleOCR 路径）
- `qwen_vl_recognizer.py:104-117` — box_level 路径也用等宽切分
- `qwen_vl_recognizer.py:940-975` — page_level 回退路径用等宽切分
- `qwen_vl_recognizer.py:796-893` — page_level 主路径**已改进**：`_rescale_chars_x_to_region` 双重触发（跨度>1.3× 或偏移>80px）线性映射，保留模型逐字相对间距
- `grader.py:111-175` — **DP 不导致坐标错位**：每个 OCR 字保留自己的 `bbox_pixel`，DP 只影响 `expected` 字段；多余字保留原 bbox 标 wrong，漏字不生成条目

**残余问题**：
- 中心点匹配 + 首匹配即停导致多 OCR 记录遗漏（handwriting_recognizer.py:110-134）
- 等宽切分在 PaddleOCR/box_level/回退路径仍存在累积偏移
- page_level 主路径 X 已改善（误差 144px → 61px），但回退路径无修正

#### 假设 4：PDF 坐标映射与文字渲染 — 不成立（已正确实现）

**用户描述的问题**：
- Y 轴翻转公式有误
- reportlab drawString 基线偏上
- 字号自适应不准
- clamp 和 rescale 引入误差

**代码实际情况**：
- `pdf_annotator.py:45-51` — Y 翻转公式 **正确**：`y_page = page_height - (y_pixel / img_h * page_height)`，符合 project.md 规则
- `pdf_annotator.py:118-121` — 基线 **正确**：`text_y = min(y0_page, y1_page) + bh * 0.2`，用底部+20%偏移（ascender ratio ≈ 0.8），**非左上角坐标**
- `pdf_annotator.py:116` — 字号 **合理**：`font_size = max(min(bh * 0.9, 24), 8)`，8-24pt 自适应
- `qwen_vl_recognizer.py:896-937` — Y clamp **混合策略**（非纯 replace）：完全偏移→replace，部分重叠→clamp，完全在内→保留
- `qwen_vl_recognizer.py:796-893` — X rescale **双重触发**（非总是启用）：仅跨度>1.3× 或偏移>80px 时介入

**用户假设的"基线偏上"不成立**：代码已用底部+20%偏移，符合 CJK 字体特性。

#### 假设 5：Qwen3-VL 坐标修正过度 — 不成立（已修复）

**用户描述的问题**：
- Y clamp 过度修正
- X rescale 线性映射失真
- 无 A/B 测试开关

**代码实际情况**：
- `qwen_vl_recognizer.py:896-937` — Y clamp **已改为混合策略**：
  ```python
  if y1 <= norm_y0 or y0 >= norm_y1:
      # 完全在 region 外 → replace
      clamped.append({**ci, "bbox_norm": (x0, norm_y0, x1, norm_y1)})
  else:
      # 部分重叠或完全在内 → clamp（保留模型 y 相对信息）
      clamped_y0 = max(y0, norm_y0)
      clamped_y1 = min(y1, norm_y1)
      clamped.append({**ci, "bbox_norm": (x0, clamped_y0, x1, clamped_y1)})
  ```
- `recognition_config.py:64-67` — **Y_CLAMP_ENABLED 开关存在**（默认 True，可关闭做 A/B 测试）
- `recognition_config.py:59-62` — RENDER_TEXT_MODE 注释 **与代码一致**：
  ```python
  # True = 将识别文字直接渲染到 bbox 位置（覆盖原文），应用 y-clamp + 条件性 x-rescale
  # False = 传统标记模式（勾/圈/三角），应用 y-clamp + x-clamp
  RENDER_TEXT_MODE = True
  ```

## 二、改进方案

基于验证结果，按优先级提出 3 项改进。**假设 4、5 已修复，无需改动；假设 2 描述过时但残余问题 F 值得修；假设 1、3 的残余风险是改进重点。**

### 改进 1：page_level 路径坐标空间统一（高优先级）

**问题**：问题 A — 当扫描有倾斜触发 deskew 时，`question_regions`/`handwriting_boxes` 在 processed_np 空间，而 Qwen3-VL 在 original_np 空间识别，导致坐标空间不一致。

**方案**：在 `pipeline_service.py` 的 page_level 分支中，**对 original_np 应用与 processed_np 相同的 deskew**，确保两空间一致。

**修改文件**：`d:\MyCode\correction\auto_marker\services\pipeline_service.py`

**具体改动**：
```python
# pipeline_service.py 第 252-256 行附近
original_np = np.array(img)
if QWEN_VL_USE_DESKEW:
    from core.image_processor import deskew_only
    original_np = deskew_only(original_np)
```

但当前 `deskew_only` 不可复用（每次调用重新计算旋转角度）。需要改造 `image_processor.py`：
1. `preprocess_image` 返回 `(processed_img, deskew_angle)` 二元组
2. 新增 `apply_deskew(img, angle)` 函数，用已知角度旋转
3. `pipeline_service.py` 用同一角度对 original_np 应用 deskew

**替代方案（更简单）**：直接在 page_level 路径用 `processed_np`，但需解除 CLAHE 禁用约束。**不推荐**（违反硬约束）。

**推荐方案**：改造 `image_processor.py` 支持角度复用，`pipeline_service.py` 对 original_np 应用相同 deskew。

**预期效果**：倾斜扫描场景下坐标空间一致，消除 17px 系统偏移。

### 改进 2：中心点匹配允许多 OCR 记录匹配同一手写框（中优先级）

**问题**：问题 F — `handwriting_recognizer.py:110-134` 的 `unmatched_boxes.pop(best_idx)` 导致一个手写框内多 OCR 记录时只匹配第一个，后续遗漏。

**方案**：移除 `pop`，允许多个 OCR 记录匹配同一手写框，按 x 坐标排序拼接。

**修改文件**：`d:\MyCode\correction\auto_marker\core\handwriting_recognizer.py`

**具体改动**：
```python
# handwriting_recognizer.py 第 110-134 行
# 移除 unmatched_boxes.pop(best_idx)
# 收集所有匹配到同一 hw_box 的 OCR 记录，按 x_center 排序后拼接字符
```

**风险**：可能导致同一手写框被重复匹配（误匹配）。需增加去重逻辑（如检查 OCR 记录的 x 范围是否重叠）。

**预期效果**：减少多行手写框的字符遗漏。

### 改进 3：page_level 回退路径等宽切分复用 X 修正逻辑（中优先级）

**问题**：问题 3 残余 — page_level 回退路径（`_equal_width_split`、`_clamp_chars_to_column`）使用等宽切分，无 X 修正，累积偏移大。

**方案**：在回退路径中也调用 `_rescale_chars_x_to_region`，复用双重触发线性映射。

**修改文件**：`d:\MyCode\correction\auto_marker\core\qwen_vl_recognizer.py`

**具体改动**：
- `_equal_width_split`（第 940-975 行）：生成等宽 bbox 后，调用 `_rescale_chars_x_to_region(answer_text=...)` 修正
- `_clamp_chars_to_column`（第 461-511 行）：列归属错误时，不再退化为纯等宽切分，而是用 marker_bbox x 范围 + 等宽切分 + rescale

**风险**：回退路径本就是异常情况，增加复杂度可能引入新问题。需充分测试。

**预期效果**：回退路径 X 误差从 ~200px 降至 ~60px（与主路径一致）。

## 五、假设与决策

### 5.1 假设

1. 测试样本 `301_2026-06-18_003.pdf` 无明显倾斜（改进 1 难以验证效果）
2. Qwen3-VL 服务在 `http://localhost:8080` 运行（E2E 测试需要）
3. 改进 2 的去重逻辑不会误删合法的多 OCR 记录
4. 改进 3 的回退路径触发频率低，风险可控

### 5.2 决策

1. **改进 1 采用"角度复用"方案**，而非"page_level 用 processed_np"（遵守硬约束）
2. **改进 2 移除 pop + 增加去重**，而非"允许多次 pop"（避免复杂状态）
3. **改进 3 复用 `_rescale_chars_x_to_region`**，而非"新写修正函数"（DRY 原则）
4. **不改进假设 4、5**（已修复，避免过度工程）
5. **不改进问题 B/C/D/E**（影响小，避免范围蔓延）

### 5.3 实施顺序

1. 改进 1（page_level 坐标空间统一）— 高优先级，但需改造 image_processor
2. 改进 2（中心点匹配多记录）— 中优先级，改动小
3. 改进 3（回退路径 X 修正）— 中优先级，需测试

每项改进后立即运行对应单元测试 + E2E 测试验证。
